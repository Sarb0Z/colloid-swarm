# Agent Scaffold Rules

## Business Invariants
- `.agents/` is the canonical home for agent configuration. Edit files here, never through a `.claude/` symlink mirror.
- Transient ledgers (`.sources-ledger`, `.wrap-state-*`, `.compaction-pending`) are runtime state. They are gitignored and must not be edited by hand.
<!-- colloid-only -->
- `.genome-ledger` and `.mutagen-ledger` are transient ledgers on the same terms.
<!-- /colloid-only -->
- `config.json` is canonical: it sets the rules for every tool, and each sync script must read it the same way — per key, so an entry stating one key inherits the rest from `config.json.example`. It is gitignored and per-repo, and tooling writes to it (`sync-mcp.sh` persists MCP toggles), so add a knob to `config.json.example` and let the local file override it. `models.*` is the one exception: it reaches committed output (`.claude/agents/*.md` frontmatter), so `sync-claude-agents.sh` reads it from the tracked `.example` alone — a local override there would commit a machine-local value and fail the drift gate on every other checkout.
- Commit generated output only when all three hold: every input is tracked, generation is deterministic, and the output holds nothing machine-local. `.codex/agents/*.toml` and `.claude/agents/*.md` qualify, because their personas are tracked. `.mcp.json`, `.kimi-code/mcp.json`, and `.codex/config.toml` do not, because they derive from the gitignored `config.json`. Ledgers, `.tsbuildinfo-claude`, and `settings.local.json` never qualify. Where output stays out of the tree, its source must be in the tree with one command that rebuilds it — `sync-claude-agents.sh`, `sync-mcp.sh`, `sync-codex.sh`.
- `.claude/agents/` is Claude Code's project-subagent directory, not the sync script's. Ownership is the `GENERATED by .agents/sync-claude-agents.sh` banner: a definition carrying it is regenerated, one without it belongs to the operator and is neither overwritten nor reported as drift, tracked or not. `sync-claude-agents.sh` deletes nothing — every data-loss defect it has shipped came from a prune reasoning about a derived set, so a stale path is named by `--check` with the `git rm` that removes it and the operator does the deleting. Every skill carries an `AGENTS.md`, which `lint-skills.sh` enforces, because `.claude/rules/<skill>.md` links at it and a missing one leaves a dangling link.
- Every skill obeys the Agent Skills format: `name` within 64 chars and matching its directory, `description` within 1024 chars and never addressing a reader (third person or the imperative; `you` outside a quoted trigger phrase is refused), `SKILL.md` body within 500 lines, reference files linked only from `SKILL.md` and carrying a `## Contents` past 100 lines. `.agents/lint-skills.sh` is the enforceable statement of these rules and the lint gate runs it on every skill edit — read the script rather than restating the limits in a skill's own `AGENTS.md`.
- A `SKILL.md` front-loads its load-bearing instructions. Post-compaction re-injection truncates a skill at 5,000 tokens and the whole set at 25,000, keeping the START of each file, so anything a long skill states near the end survives the first load and not the second.
- A guard ships with a test that goes red when the guard is removed. A suite that passes says nothing about whether it would fail, so a guard nothing exercises is a green light wired to nothing and the suite covering it reports success while measuring an absence. `test-mutation.py` is the enforceable statement: one row per guard, each naming the text that implements it, the text that neutralizes it, the suite that must then fail, and the fragment that suite must print. It runs a control pass first — a suite that does not pass unmutated cannot certify anything — and only `PROTECTED` passes: `UNPROTECTED` (nothing covers the guard), `INCONCLUSIVE` (the suite failed for another reason), `VACUOUS` (the fragment appears in the passing run too, so any non-zero exit would satisfy the row), `STALE`, `TIMEOUT`, and `CONTROL-FAILED` all fail the build. `UNPROTECTED` blocking is the rule enforcing itself; it does not mean the guard is dead, because dead means a firing case cannot be written and only the attempt settles that — so a new guard arrives with its row, or it does not arrive.
- The party being graded does not edit its own grader. `hooks/policy/grader-lock.sh` refuses a spawned subagent any write to the standard, the gates, the transport that reaches a gate, and the tests that prove a gate fires; a skill stays writable, because `lint-skills.sh` grades a skill and that script is itself governed. Amending the standard is the operator's act through the main session, and it ships as its own change rather than folded into the work that standard is grading. The lock sees `Edit` and `Write` alone: a shell redirect reaches the same files, so it is a guardrail against writing the rules by accident, never a boundary against one that means to.
- A check's price decides where it runs. A cheap check belongs in the loop, on every edit (`hooks/policy/post-edit-check.sh`); an expensive one batches into its own phase with a single owner (`playbooks/hostile-review.md`). Placing a new check is a cost question before it is a taste question. The second effect is the one that surprises: an agent that *can* run the expensive check starts working to satisfy that check instead of the standard, so keeping it out of the loop protects the work as much as the machine.

## Abnormal Cases and Rationale
- Skills and hooks are read through symlinks by Claude Code. A broken symlink means a missing canonical file, not a missing symlink.

## Out of Scope
- Do not restate the layout table in `.agents/README.md`. This file governs invariants, not inventory.
