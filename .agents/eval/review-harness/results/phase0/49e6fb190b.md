## Hostile Review Report

**Artifact:** `src/app/dashboard/connect/page.tsx` diff (CHANGE.diff) — CleanStack-web "Disconnect" button

### Findings

1. **`src/app/dashboard/connect/page.tsx:203`** — `className="btn btn--danger"` references a class that does not exist anywhere in the codebase. `grep -rn "btn--danger" "$TREE"` matches only this one usage; `src/app/globals.css` defines `.btn`, `.btn--ghost`, `.btn--block`, and nothing else — no `.btn--danger`, no `@apply`, no Tailwind utility of that name (Tailwind v4 is imported but the `.btn*` family is hand-authored BEM, so nothing auto-generates it). The result: the "Confirm disconnect" button silently falls back to bare `.btn`, which is styled `--btn-bg: var(--pine)` — the identical deep-green background used by the primary "Connect Google Workspace"/"Reconnect" action. It bites because the entire point of this control, stated explicitly in the plan ("a mis-click costs a full Workspace-admin re-consent, so I'm guarding it"), is defeated: the one visual signal that should distinguish an irreversible destructive action from the routine primary action (color — matching the `var(--red)` already correctly applied to the footnote text one line above it) is absent. This is not "existing button styles" as the plan claimed, nor a deliberate new primitive — it's a dead class reference that degrades to the wrong existing style. Fix: add the missing rule to `globals.css`, mirroring the `.btn--ghost` pattern, e.g. `.btn--danger { --btn-bg: var(--red); --btn-fg: var(--paper); }` plus a hover shade (there's no `--red-bright` token yet — add one or reuse `--red` with an opacity/hover treatment consistent with `--pine-bright`).

2. **`src/app/dashboard/connect/page.tsx:190-238`** — The "Confirm disconnect" button lands in the exact same flex slot (rightmost, primary position) previously occupied by "Reconnect"/"Connect". Once finding 1 is fixed the color cue helps, but position is still identical to the routine primary action a returning user clicks reflexively. For a confirm step guarding an admin-re-consent-costly action, same-slot placement is a known anti-pattern (fast double-click or muscle memory can land on "Confirm disconnect" instead of what the user expects). Not a hard bug — the plan explicitly traded a distinct/delayed confirm UI for reusing existing button styles — but worth a deliberate decision rather than an accidental byproduct of finding 1. Lower priority than 1; flagging for disposition, not blocking.

3. **`src/app/dashboard/connect/page.tsx:109-113`** — The `catch` block for `disconnect()` swallows the actual failure (network error, 401, 429 from the stated 10/min throttle, 5xx) into one generic banner string with no `console.error`/logging. If the disconnect silently fails in production (e.g., rate-limited, or Google revoke succeeded but Vault delete/row flip failed server-side leaving a partial state), there is no client-side trail to distinguish "user retried into a live rate limit" from "the org is now in an inconsistent connected/no-token state." This mirrors the pre-existing `connect()` pattern, so it isn't a regression introduced by this diff, but it's now guarding a destructive/irreversible action rather than a read-only status fetch, so the debuggability bar is higher. Minor; note only.

### Non-findings worth stating explicitly

- Optimistic state update (`setStatus('disconnected')`/`setConnectedAt(null)` instead of re-calling `loadStatus()`) is consistent with the backend's documented transaction order (row flipped before the 200 is returned per REVIEW-INTENT.md) — acceptable, not a drift risk.
- Scope matches the stated intent: no changes to audits/tools/directory rows, no new backend surface introduced in this diff (backend is out of scope of CHANGE.diff, per intent already-implemented).
- No dead code, no tombstone comments, no backwards-compat shims — complies with the repo's CLAUDE.md bar on that axis.
- Access control, abuse/limits, race conditions, queries, and pagination axes have nothing to say — this diff is a client component with no server logic; the backend contract (bearer-guard, throttle, org-from-session, idempotency) is asserted in the intent doc but not present in this diff's file set to independently verify.
