2. **`src/app/dashboard/connect/page.tsx:190-238` — focus and screen-reader state loss on the Disconnect → Cancel/Confirm swap.** The ternary unmounts/remounts a structurally different Fragment, so keyboard focus drops to `<body>` on both transitions, and there's no `aria-live` region announcing that the button under the user's cursor/focus just changed meaning — risky for a flow whose whole point is deliberate friction before an irreversible action.

3. **`src/app/dashboard/connect/page.tsx:88-118` — no resync on network failure after a possibly-successful server-side revoke.** If the POST throws after Google/Vault/DB state has already changed server-side (e.g. connection drop on the response), the catch block never calls the existing `loadStatus()` to resync, so the UI can keep showing `Connected` against a dead grant — reintroducing client-side the same lazy-staleness bug the backend rewrite was meant to kill server-side.
