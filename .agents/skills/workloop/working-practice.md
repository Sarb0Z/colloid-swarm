Working practice:
- Run the brief's acceptance, iterating on the narrowest test that covers the failure: one test, file or package. In a run, run nothing broader: integrate runs the composed test once over the merged tree. Outside a run, run a full suite only when the brief names it, once, before returning. When one acceptance run costs over a minute, say so in your result.
- Start a server, a watcher, or anything else that does not exit where your host can see and stop it, never in the foreground. Claude Code: a Bash call with run_in_background: true. Codex: nohup <cmd> > <log> 2>&1 & echo $!, and keep the process number. Wait until it is ready under a capped poll, such as timeout 120 bash -c 'until curl -sf <url> >/dev/null; do sleep 2; done', and stop it before you return: TaskStop where you have it, otherwise kill its process.
- A command that ends within 10 minutes runs in the foreground with a timeout that covers it (Claude Code's Bash default is 2 minutes; set timeout up to 600000). A longer one starts in the background and prints its own end marker, <cmd>; echo "exit=$?"; wait for it in polls of at most 10 minutes: timeout 590 bash -c 'until grep -q "^exit=" <output>; do sleep 5; done'.
- Edit a file with your host's edit tool: Read, then Edit or Write in Claude Code; apply_patch in Codex. A shell script writes only the output a command generates; a source file written from the shell skips the post-edit hooks.
