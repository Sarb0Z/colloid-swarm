# iTerm2 console spec: plan review rounds 1 to 3

Plan `docs/notes/2026-11-15-iterm2-review-and-status-spec.md`, before any
implementation. Critical stakes. One reviewer (opus) per round, each a fresh
cell that read the plan whole against the repository, the machine files it
cites and the external sources it could reach. No code exists yet, so this
record carries no `Covers:` line.

## Round 1 (spec sha256 `50a5c6d3…`)

The plan ran pane reviews and other read-only entries in a separate Claude
session in iTerm2's Code Review pane, and pasted findings into the tab's
session with iTerm2's auto-send.

| # | Sev | Finding | Disposition |
|---|---|---|---|
| 1 | P0 | Delivery pasted text and pressed Return when the lead was "not working", which includes a pending permission prompt, so a Return could approve a `git push`; it also merged with a half-typed draft | Adopted: no delivery through the input line |
| 2 | P1 | Pasted reviewer text carried the operator's authority; the header did not prevent it | Adopted: nothing is pasted |
| 3 | P1 | Per-finding clippings dropped the contract's report lines; a failed reviewer looked like `FINDINGS: none` | Moot: the reviewer reports to the lead as usual |
| 4 | P1 | Records from pane reviews could clear critical scopes without the ask, the plan or the disprove pass | Adopted: the lead runs the full procedure |
| 5 | P1 | The frozen diff did not freeze what the reviewer read | Adopted: snapshot worktree |
| 6 | P1 | The stated trade-off behind the operator's first ruling was false: a background cell runs while the lead keeps working | Adopted: re-asked; the operator chose the lead |
| 7 | P1 | `idle_prompt` replaced an open gate with `done` | Adopted: recalculate from the transcript |
| 8 | P1 | Gates asked through the question tool were not detected | Adopted: PreToolUse registration |
| 9–23 | P2 | Base mismatch, read-only skill list, artifact outside the launch folder, tab lookup by folder, selector spoofing, contract extractor in satellites, review loop, unbounded wait, state file lifecycle, stakes of units 2 and 3, global menu ownership, a miscount, STE and modals, loop cost, prompt quoting | Adopted where the redesign kept the part; moot where it removed it |

## Round 2 (spec sha256 `5aca96be…`)

The plan sent requests to the lead through an asynchronous Stop hook that
woke the lead with `asyncRewake`.

| # | Sev | Finding | Disposition |
|---|---|---|---|
| 1 | P1 | Claude Code enforces the hook `timeout` on `asyncRewake` hooks (600 s default), so a Start after ten idle minutes woke nothing and the request reached a later turn | Adopted: the waiter is replaced by Claude Code's cross-session messaging, which starts a turn in an idle session |
| 2 | P1 | Stop does not mean the turn ended (sibling Stop blocks, turns without a prompt, StopFailure, fresh sessions); claim by rename was at-most-once | Adopted: same replacement; delivery semantics are Claude Code's |
| 3 | P1 | Any process running as the operator could drop a request that woke the lead in the operator's voice | Adopted: a cross-session message is marked as from another session and cannot approve anything or change configuration |
| 4 | P1 | Unit 4's critical scripts had no repository, so no record, test or undo could cover them | Escalated; the operator ruled: colloid-swarm, carrier-only folder, suite tests, install step |
| 5 | P2 | iTerm2 writes its whole prompt list back on every in-app change, and lists prompts in array order | Adopted: write only while iTerm2 is not running, in group order; P7 adds an in-app edit |
| 6 | P2 | The loop guard blocked a second review the operator chose | Adopted: guard removed; R2 and Claude Code's repeat throttling cover the loop |
| 7 | P2 | The Lenses line let a partial pane review stand in for the delivery review | Escalated; the operator ruled: only a review of the whole scope, unchanged since |
| 8 | P2 | `idle_prompt` does not fire while a background agent counts as running, and dead read-only cells are not named | Escalated; the operator ruled: turn end only, plus the count |
| 9 | P2 | `--if-turn-open false` would refuse the question-tool write on later iTerm2 | Adopted: the flag value follows the event |
| 10 | P2 | Unit 2 lacked the tab's-own-Claude check | Adopted |
| 11 | P2 | Gate deduplication had no key | Adopted: normalized gate text; a recheck before alerting |
| 12 | P2 | The new ledger prefix was missing from `worktree_heal.py` LEDGERS and the README | Adopted |
| 13 | P2 | The snapshot worktree had no teardown | Adopted: registered for teardown |
| 14 | P2 | The non-harness review had no source for iTerm2's review prompt | Adopted: the command passes it |
| 15 | P2 | No export of the saved prompts before the first write | Adopted |
| 16 | P2 | Loop costs lacked runs per day | Adopted: stated from this machine's transcripts |
| 17 | P2 | Skill count, a missing findings row, a wrong citation, and machine rows read by the lead | Adopted: a fresh cell re-read the machine rows |
| 18 | P2 | Glossary and the spec disagreed on "open gate"; "leader" and "lead" both used | Adopted |
| 19 | P2 | Acceptance 1 ignored untracked files | Adopted |

The fresh cell that re-read the machine rows corrected one: iTerm2's hook at
turn end took 22–39 ms in 7 of 14 runs and 0.3–1.3 s in the other 7, not
"about 25 ms".

## Round 3 (spec sha256 `e917bf51…`)

The plan posted requests to the lead's inbox socket as cross-session messages
whose text claimed the operator pressed Start, with a UserPromptSubmit hook as
the fallback channel. The reviewer posted to no socket and sent nothing; its
one outward call read the cross-session messaging page, which the lead
re-read before the dispositions.

| # | Sev | Finding | Disposition |
|---|---|---|---|
| 1 | P1 | The message text claimed the operator's authority, and nothing the pane sends can prove it: any process of the operator's user, or another Claude session, can post the same line. Third round with this shape (round 1 #2, round 2 #3) | Escalated under the three-round rule; the operator ruled R19: everything runs on Start, as the operator's own request, accepting forgery; permission prompts, gates, outward actions and configuration still need the operator's own message |
| 2 | P1 | The fallback put queued requests into the lead's context as hook context with no from-another-session label | Adopted: fallback deleted; a failed P2 returns unit 4 to the operator |
| 3 | P2 | No contract line said how the lead treats a pane request | Adopted: 4g names the line, its home `.agents/claude/delegation.md`, and its fresh-session test |
| 4 | P2 | A held message expires after five minutes with no signal to the poster; plan mode counts as bypassing | Adopted: E9, 4a.7, P2 and Acceptance 30 |
| 5 | P2 | A stale tab record or a reused pid could reach the wrong session | Adopted: liveness and `sessionId` checks; Acceptance 32 |
| 6 | P2 | Claude Code drops an identical repeat, which broke Acceptance 27 | Adopted: the pane says so; no request id, so a double press runs once; Acceptance 27 names two entries |
| 7 | P2 | The Diff pane and a pane review used different bases on a branch with no upstream | Adopted: one `pane-base`, as the operator's option "Not pushed, like reviews" said |
| 8 | P2 | `\(codeReviewModelFlag)` does not exist on 3.7.7 | Adopted: the entry header sets the model |
| 9 | P2 | No source for the ask and plan of a pane review | Adopted: quoted ask and plan file, or the record cannot stand in |
| 10 | P2 | A turn the operator did not start can drop an open gate's status | Adopted: known gap stated; Acceptance 29 |
| 11 | P2 | No rule for Start in a satellite | Adopted: 4f; Acceptance 31 |
| 12 | P2 | This record named probe P8, which does not exist | Adopted: P7 |

Measurement: the spec is over 300 lines. Accepted: its four units share the
rulings, the request channel and the acceptance numbering, and a split would
