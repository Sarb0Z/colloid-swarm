## The fixes

The writer landed `4cccf3a` (findings 1–8, 10, 11 and the lead's line) and
`677ec51` (finding 9 and the breadcrumb's count, now 413 lines). A full run
then found two failures that only happen in the copy, fixed in `0ff4436`:

- bash starts a background command with SIGINT ignored, and every check
  inherited it, so a nested `suite.sh` could not be interrupted. The checks'
  session leader restores SIGINT and SIGQUIT to their defaults.
- `scrapling-mcp.py` drops every `PLAYWRIGHT_` variable and finds the browsers
  under `HOME`, so `test-scrapling-proxy.sh`'s browser rows failed with
  "Executable doesn't exist". `suite.sh` clones the browser folder to its
  default place in the temporary home (`cp -cR` on macOS, an APFS clone; the
  writer timed 0.16 s for 770 MB) and points `PLAYWRIGHT_BROWSERS_PATH` there.

The clone departs from the design, which kept the real folder. The lead
accepts it: it meets the design's reason, that nothing downloads and no
browser layer skips, and a check's write to the browsers stays in the
temporary home. Off APFS, or on Linux without reflink, the clone is a full
copy each run; no such run exists, since `suite.sh` runs only here (G6) and
CI runs each check as its own step. The plan's design now says so.
